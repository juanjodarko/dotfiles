Omarchy 4 reality — it's one shell

Quattro replaced the separate waybar / walker / mako / swayosd / hyprlock / polkit-agent stack with one long-running Quickshell process, omarchy-shell. Everything on screen is a plugin inside it: omarchy.bar, .menu, .lock, .osd, .polkit, .notifications, .clipboard, .emojis, .panels, .reminders, .background, .services, .agents. (Confirmed by base.packages: quickshell present; no mako/swaync/waybar/walker/swayosd/hyprlock.)

Consequences that shape the whole plan:

  • "The bar" and "the plugins" are the same thing. Wanting them = adopting omarchy-shell as the desktop shell — the heaviest, most Omarchy-coupled piece (assumes $OMARCHY_PATH, ~/.config/omarchy/, the omarchy-* bin suite).
  • Modularity is the escape hatch. Keep our own tools by disabling the matching plugin: omarchy.notifications → swaync, omarchy.lock → hyprlock, launcher → Vicinae. Only one daemon owns each DBus name.
  • Plugins are QML, distributed git-first via omarchyplugins.com (omarchy plugin add <url>) — a different ecosystem from Vicinae's TS/React store. The two are complementary: Vicinae = launcher + its extensions; omarchy-shell = bar + QML desktop plugins.

Full feature audit, ranked easiest→hardest to graft: migration/omarchy-feature-migration-map.html

The fork (leaning (b)): the bar and its marketplace are only usable by running omarchy-shell — a Quickshell config coupled to $OMARCHY_PATH + the omarchy-* suite (the omarchy-shell command is just an IPC forwarder; Hyprland launches it as quickshell -p $OMARCHY_PATH/shell). So we lean to a standalone Quickshell bar, not omarchy-shell. To still benefit from the marketplace, the plan is to fork individual Omarchy plugins onto plain Quickshell via a small compat shim — a plugin-loader + a Theme/Config singleton mapped to our Catppuccin current.*. Script-driven bar-widgets port nearly verbatim; feasibility + shim shape in dossier §K. migration/decruft-dossier.md

Roadmap (revised)

Week 1Safety net + de-cruft

Goal: a verified backup, a tagged snapshot, and a lean main repo you fully understand.

  1. Full system backup, verify-restore first. Manifests (pacman -Qqe, -Qqm — already captured in migration/manifests/); home/data to an external drive via restic (migration/omarchy-backup.sh); test-restore a sample path — the real gate.
  2. Tag: git tag pre-omarchy-2026 && git push origin pre-omarchy-2026.
  3. De-cruft on a cleanup branch, category by category (A–F), per-item approved. Already done ahead (git-reversible): kitty 0e4a58a, bin wrappers 1012182. Decide the open items: settings, vim/.vimrc, bash/.
  4. Review the full cleanup diff together, then merge.

Deliverable: verified backup + pre-omarchy-2026 tag + merged cleanup.

Week 2Omarchy VM + validate the omarchy/ track + Vicinae (early win)

Goal: prove the branch installs cleanly and reversibly on real Omarchy 4; land the cheapest high-value change.

  1. Build + snapshot the VM (QEMU/virt-manager) on Omarchy 4.x; verify version.
  2. Deploy the branch: omarchy/install.sh --dry-run → review → real run. Confirm ALT bindings, starship/lazygit/ghostty/bat retint, wallpaper seeding, clean hyprctl configerrors. Round-trip via uninstall.sh + snapshot revert.
  3. Vicinae — prototype early & independently (low-risk, no shell swap): install, bind = SUPER, SPACE, exec, vicinae toggle, and lift the sketch in migration/vicinae-hyprland-extension/ (Switch Window / Switch Theme). De-risks the launcher question before the big shell decision.
  4. Prereq refactor: extract a headless bin/.local/bin/theme-set <flavor> from wofi-theme-switcher.sh so wofi, Vicinae, and any future bar share one backend.

Deliverable: install.sh/uninstall.sh green on a real Omarchy 4 VM + Vicinae driving the launcher.

Week 3Stack in the VM + onboard to QML

Goal: the desktop we actually want, proven in the VM; ability to build a QML plugin.

  1. Deploy the file-manager stack (staged in migration/planned-yazi/): yay -S yazi + Nautilus stacks; move the themes/config into place; apply the 5 switcher edits; yazi on the switcher, Nautilus for GUI moments.
  2. Stand up a standalone Quickshell bar (not omarchy-shell): built from scratch on Quickshell, cribbing config/theming patterns from end-4/dots-hyprland & doannc2212. Stretch: a plugin-loader + Theme/Config shim so wanted Omarchy plugins can be forked to run outside Omarchy (dossier §K). Keep swaync + Vicinae.
  3. Learn QML by cloning a built-in: omarchy plugin clone omarchy.clock --edit; read manifest.json + QML entry points; omarchy plugin validate + qmllint; lifecycle loop.
  4. Scaffold the GPU-mode switcher bar-widget (io.github.juanjodarko.gpu-mode) on the shared gpu-mode-set backend — step 3 of "GPU switcher — build order" (waybar version ships earlier; both gated behind the driver migration).

Deliverable: yazi/Nautilus live in VM, an omarchy-shell keep/drop verdict, a working GPU-mode widget.

Week 4Publish the plugin + plan the real cutover

Goal: one shared plugin, a tidy repo, and a written (not executed) cutover runbook.

  1. Ship the plugin: validate + qmllint clean, README + LICENSE, publish to its own repo, install via omarchy plugin add <url> --enable, list on omarchyplugins.com.
  2. Repo strategy: merge omarchy-quattro's omarchy/ into main (root = plain-Arch packages, omarchy/ = Omarchy-native); delete stale branches.
  3. Write the laptop cutover runbook (execute later, your call): fresh backup → fresh Omarchy 4 → clone → stow portable packages + omarchy/install.sh → restore personal data → keep the old desktop as a week-long fallback before wiping the last backup.

Deliverable: published plugin + consolidated repo + a runbook you can run when ready.
