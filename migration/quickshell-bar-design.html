§1Why Quickshell, and what we're building

The whole ricing scene consolidated onto Quickshell in 2025–26 — end-4/dots-hyprland migrated off AGS to it, the Fabric-based Ax-Shell is archived. It's a QML toolkit for Wayland shells: you declare windows, widgets and OS services as a QML tree; it hot-reloads on save. That's the right foundation for the §K goal — our own bar with switcher-driven theming and (later) TUI integrations, none of Omarchy's coupling.

  • Target: feature-parity with your waybar (~20 modules), + the GPU-mode switcher as the first custom widget.
  • Philosophy (same as your theme switcher): thin QML frontends over your existing scripts + Quickshell's built-in service singletons. Little new backend code.
  • Keep what works: swaync (notifications), Vicinae (launcher), hyprlock/hypridle — the bar does not absorb them.

§3Architecture — one bar per monitor

Entry is a Scope holding shared singletons/processes, with a Variants over Quickshell.screens that instantiates one PanelWindow (layer-shell bar) per monitor — auto-created/destroyed on hotplug. Each bar binds to its Hyprland monitor via Hyprland.monitorFor(modelData).

// shell.qml — the skeleton
import Quickshell
import Quickshell.Hyprland
import QtQuick

Scope {
  // shared, NOT per-monitor: put Timers / Process readers / service refs here
  Variants {
    model: Quickshell.screens
    PanelWindow {
      required property var modelData              // the ShellScreen
      screen: modelData
      readonly property HyprlandMonitor monitor: Hyprland.monitorFor(modelData)
      anchors { top: true; left: true; right: true }   // full-width top bar
      implicitHeight: 32
      color: Theme.base                            // live-themed (§4)
      RowLayout { anchors.fill: parent; anchors.margins: 8
        Workspaces { barMonitor: monitor }         // left
        WindowTitle { visible: monitor && monitor.focused }
        Item { Layout.fillWidth: true }             // spacer → center/right groups
        GpuMode {}  Volume {}  Battery {}  SysTray {}  Clock {}
      }
    }
  }
}

§4Live theming — the keystone (§K north star)

The bar must repaint instantly when your Catppuccin switcher flips flavors. Quickshell gives us exactly the tool: a Theme singleton using FileView { watchChanges: true } + JsonAdapter that exposes typed color properties; every widget binds color: Theme.mauve and re-tints with no restart.

// Theme.qml — singleton, live-reloading Catppuccin palette
pragma Singleton
import Quickshell
import Quickshell.Io
Singleton {
  readonly property color base:     adapter.base
  readonly property color text:     adapter.text
  readonly property color mauve:    adapter.mauve
  readonly property color lavender: adapter.lavender   // …one per Catppuccin role
  FileView {
    path: Quickshell.env("HOME") + "/.config/themes/current.json"
    watchChanges: true
    onFileChanged: reload()
    JsonAdapter { id: adapter
      property color base: "#303446"; property color text: "#c6d0f5"
      property color mauve: "#ca9ee6"; property color lavender: "#babbf1"
    }
  }
}
⚠ One prerequisite: the switcher must emit a real current.json (not a symlink)

Your switcher flips a symlink current.conf → catppuccin/<flavor>.conf. Qt's file watcher can miss a symlink relink (it sees a removal and drops the watch). Fix — add one step to the switcher: ship catppuccin/<flavor>.json palettes and write current.json as a real file via atomic replace (cp to a temp, then mv over it) on every switch. Atomic-rename reliably fires the watcher. This is the same "add a per-app target to the switcher" pattern as kitty/yazi, but here a copied JSON, not a symlink.

Fallback (no switcher change): point FileView at current.conf and regex the $name = rgb(hex) lines in onLoaded — works, but stringly-typed and exposed to the symlink flakiness. The atomic-JSON route is cleaner and is the recommendation.

Recommended shape: adopt Omarchy's colors.toml semantic-role palette

Omarchy 4 (MIT) themes everything from one central colors.toml with ~22 semantic keys (accent, background, foreground, selection, muted, urgent + named colors), and its bar binds to roles (bar.background, bar.accent) — not to "mauve". Do the same: have the switcher emit a semantic palette (Catppuccin values mapped into those roles), and bind bar widgets to roles. Two payoffs:

  • Portable across both worlds (the migration goal): the Theme singleton reads a colors.toml-shaped file — off Omarchy your switcher writes it from Catppuccin; on Omarchy you point it at ~/.local/state/omarchy/current/theme/colors.toml. Same bar, correct theme in both.
  • Theme-agnostic: stay Catppuccin now, but you could later drop in any of Omarchy's 22 MIT theme palettes (Catppuccin, Tokyo Night, Gruvbox, Nord, Everforest, Kanagawa, Rose Pine, Matte Black…) with zero bar changes.

Reference impl to crib (MIT): bjarneo/quickshell is a standalone Quickshell bar that watches Omarchy's live colors.toml and re-tints on omarchy theme set — exactly this mechanism, copyable.

Later (§K north star), a shell-tokens.json split (design tokens: spacing, radii, animation, bar height) can sit alongside the palette — mirroring Omarchy's colors.toml (palette) + shell.toml (surface/spacing roles) split — so the look is fully data-driven. Omarchy also renders per-app configs from the palette via .tpl templates ({{ accent_strip }}, {{ accent_rgb }}, {{ mix background foreground 15% }}) — a clean pattern to crib if you ever want the switcher to theme more apps from one palette.

§5Empty bar → plugins, core & multi-user

Design pillar: the bar renders nothing but a slot host. What shows is whatever shell.json lists, mounted from plugins. The simplest bar is two things — workspaces + system-control — and you grow it with bar plugin add …. Full spec: migration/planned-bar/README.md.

shell.json ─ modules:{ left:["core.workspaces"], center:[], right:["core.syscontrol"] } │ PluginRegistry (host singleton) scans ~/.config/quickshell/plugins/<id>/ + core/ → reads each manifest.json │ instantiate entry QML by kind, inject Theme/Config/Hyprland ▼ Bar mounts the bar-widget instances shell.json names, in order
  • Plugin = a git repo with manifest.json ({id, name, version, kind, entry, author}; kind ∈ bar-widget/panel/service) + QML, installed to ~/.config/quickshell/plugins/<id>/.
  • Host singletons injected into every plugin — Theme (§4 palette), Config, Hyprland. This mirrors Omarchy's injected Color/Style/shell, so a compat shim can host forked Omarchy widgets (dossier §K) — our plugin system and the Omarchy-fork goal are one machine.
  • Only core.workspaces + core.syscontrol are built-in. Clock, battery, audio, tray, gpu-mode, cpu, media… are all plugins (our own first-party repos or third-party).

The plugin CLI — bar (Omarchy-style, headless backend)

bar plugin add <git-url>     # clone → plugins/<id>/, validate manifest, enable in shell.json
bar plugin list            # installed + enabled/disabled
bar plugin enable  <id>      # add to shell.json module list  (hot-reloads, no restart)
bar plugin disable <id>      # remove from shell.json (keeps files)
bar plugin remove  <id>      # rm dir + drop from shell.json
bar plugin update  [<id>]     # git pull one/all

A small script (bin/.local/bin/bar), same "one backend, thin frontend" shape as theme-set/gpu-mode-set. Because the manifest vocabulary matches Omarchy's, bar plugin add <omarchy-plugin-url> can host a forked Omarchy widget once the shim maps its host imports. ⚠ Git plugins run unsandboxed QML — validate the manifest & review third-party QML before enabling.

✅ core.syscontrol — the multi-user differentiator (why not Omarchy)

Click → Lock · Logout · Switch user · Suspend · Hibernate · Reboot · Shutdown (extends power-menu.sh). systemd-logind already runs concurrent sessions, and SDDM implements the freedesktop org.freedesktop.DisplayManager API — so switch-user opens a fresh login on a new VT while your session stays alive, and existing users are reachable with loginctl activate. Omarchy doesn't expose this at all.

# new login (keeps current session):
busctl call org.freedesktop.DisplayManager /org/freedesktop/DisplayManager/Seat0 \
  org.freedesktop.DisplayManager.Seat SwitchToGreeter
# switch to an already-logged-in user:
loginctl list-sessions ; loginctl activate <session>

⚠ Verify the SDDM seat path + that SwitchToGreeter is wired in your build; fallback = hyprlock + chvt to the greeter VT. A session-control.sh backend holds the logic.

⚠ Two hard constraints from the framework
  • Do NOT enable Quickshell's NotificationServer — it's a full org.freedesktop.Notifications daemon and would fight swaync. You're keeping swaync, so the notification widget just toggles it via swaync-client. Same for tray: run only one SNI host (Quickshell's).
  • Single process: the whole bar + the SNI host is one qs process — one unhandled QML error takes it down. Keep widgets isolated, lean on hot-reload + per-widget DefaultTheme/fallback so a reload is cheap.

§7Per-monitor workspaces — core.workspaces (split-monitor-workspaces)

The Hyprland service reads real IPC, and split-monitor-workspaces creates real per-monitor workspaces each carrying a monitor. So filter by monitor.name. Gotcha: the plugin offsets workspace ids per monitor, so filter by monitor.name, key the Repeater on id, but display name — never assume id == label.

// Workspaces.qml — bound to this bar's monitor
property HyprlandMonitor barMonitor
readonly property var wss: Hyprland.workspaces.values
    .filter(w => w.monitor && w.monitor.name === barMonitor.name)
    .sort((a,b) => a.id - b.id)
Repeater { model: wss
  delegate: Text {
    required property var modelData
    text: modelData.name                        // label, not id
    color: modelData.focused ? Theme.mauve : Theme.overlay
    MouseArea { anchors.fill: parent
      onClicked: Hyprland.dispatch("split-workspace " + modelData.name) }
  }
}

§9Build phases (incremental, waybar stays until parity)

P0Palette + empty hello-bar

pacman -S quickshell. Ship the 4 palette JSONs (done — planned-bar/palettes/) + the switcher current.json atomic emit (§4 prereq). Minimal shell.qml: an empty PanelWindow on one monitor; confirm hot-reload + exclusive zone.

P1The machine: Theme + registry + CLI + core

Theme.qml live-reading current.json (flip a flavor → repaint); the PluginRegistry + the bar CLI; and the two core widgets — core.workspaces (per-monitor, §7) and core.syscontrol (multi-user, §5). This is the simplest usable bar and proves the plugin machine, live theming, and the two hardest integrations at once.

P2First-party widget plugins (built-in services)

As bar-widget plugins: clock, battery (UPower), volume (Pipewire), tray (SystemTray), media (Mpris), network, bluetooth, idle-inhibitor, window-title, submap. Mostly free — one small plugin each, added via bar plugin enable.

P3Script-backed plugins + GPU-mode ships

Plugins wrapping existing scripts via Process: temp, cpu, backlight, audio-router, update, fingerprint, notify(swaync). Land the GPU-mode switcher as a plugin on the gpu-mode-set backend — the switcher finally ships here.

P4Per-monitor polish + parity cutover

Two bars via Variants, per-output widget sets, the powerline/separator aesthetic, popups (calendar, audio mixer). Reach the parity you want → swap the Hyprland exec-once from waybar to qs; keep waybar one release as fallback.

LaterNorth star (§K)

shell-tokens data-driven config + an in-app Settings dashboard (ekremx25 pattern); TUI integrations (drop-down terminal panel for btop/yazi/lazygit via Process); the Omarchy-plugin shim so bar plugin add <omarchy-url> hosts forked widgets (dossier §K).

§10Risks & gotchas (all known, all manageable)

RiskMitigation
Single-process crash takes the whole bar downIsolate widgets; per-widget fallbacks; hot-reload dev loop; keep waybar as instant fallback until parity.
Quickshell breaks on Qt ABI bumpsUse the repo quickshell package (rebuilt with Qt), not quickshell-git.
Symlink theme flip missed by the file watcherSwitcher writes current.json as a real file, atomic mv (§4) — dodges it entirely.
