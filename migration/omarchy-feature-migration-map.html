Omarchy Feature Migration Map

Every feature and moving part Omarchy ships — sorted from easiest to hardest to graft onto an existing Arch + Hyprland system, without installing Omarchy itself. The ranking assumes what you already run: a central Catppuccin theme switcher, Waybar, rofi + wofi, kitty + ghostty, Neovim, tmux, starship.

Source: omacom/omarchy@quattro Bundled pkgs: ~180 omarchy-* CLI: ~150 scripts Audited: 2026-09-03
Guardrails still hold.

This is a read-only map, not a to-do list. Nothing here is installed. Anything that touches live config or system state goes through the same gate as the rest of the migration: cherry-pick per-item, on a branch, after the verified backup — Omarchy lives in a VM until a deliberate cutover. Adopt premises, not the whole distro.

0 Already yours
Parity done or trivial — your setup already covers it. Confirm & align, don’t rebuild.
1 Install a package
One pacman -S / yay -S away. Pure additive, zero config risk.
2 Drop-in config
Copy a config file or extend your theme switcher. Small, reversible.
3 Vendor a subsystem
Adopt Omarchy scripts/tooling that assume its layout. Cherry-pick & adapt.
4 Swap a subsystem
Replace a component you already run, or wire in system services. Real work.
5 Reinstall-level
Filesystem / bootloader / firmware territory. Not cherry-pickable without a rebuild.

4

Swap a whole subsystemeffort: replace a component / enable services

Now it costs something real: replacing a component you already run or standing up system-level services. Reversible, but each is a project with its own testing. The headline here is omarchy-shell — the one swap that carries the bar and the whole plugin ecosystem. This is exactly what the VM is for — prove it there first.

🐚 omarchy-shell — the whole desktop shell

Omarchy 4 core One long-running Quickshell process hosting everything on screen as plugins: bar, drop-down panels, launcher/menu, emoji + clipboard overlays, lock screen, polkit dialog, OSD, notifications, reminders, background, headless services. IPC-scriptable via omarchy-shell.
quickshellomarchy.baromarchy.menuomarchy.lockomarchy.osdomarchy.polkitomarchy.notifications
Migrate biggest single swap the bar + plugins you want come as this shell — it subsumes Waybar, Walker/rofi/wofi, mako, swayosd, hyprlock and the polkit agent at once. Most Omarchy-coupled piece: assumes $OMARCHY_PATH, ~/.config/omarchy/ and calls the omarchy-* bin suite. Prototype in the VM first.

🧩 Plugins — keep the surfaces you like

Omarchy 4 First-party plugins in $OMARCHY_PATH/shell/plugins/; yours in ~/.config/omarchy/plugins/<id>/. Manage with omarchy plugin list|enable|disable + omarchy-shell shell rescanPlugins (or menu → Setup → Plugins).
This is the win Modularity lets you take the bar and drop what you don’t want: omarchy plugin disable omarchy.notifications → keep swaync; same pattern for omarchy.lock (keep hyprlock), omarchy.osd, launcher. Only one daemon owns each DBus name, so disable the plugin wherever you keep your own tool.

5

Reinstall-level / not cherry-pickableeffort: rebuild the machine

These live at the filesystem, bootloader, or firmware layer. On a running system you don’t adopt them — you’d re-provision the disk. This is the strongest argument for keeping Omarchy in a VM: it’s the only place you get these as Omarchy does them, without touching your real laptop.

Reality check. You already have a working Arch install. Everything below assumes Omarchy’s opinionated provisioning — adopting it means reinstalling, which the guardrails explicitly rule out for the real laptop. Evaluate in the VM; don’t retrofit.

💽 Installer / ISO

Omarchy One-command Arch bootstrap (install/: config, hardware, login, post-install, provisioning) → full desktop.
Migrate N/A its whole job is the fresh install you’re not doing. It’s the source you mine, not a thing you run.

🗂️ Disk layout: Btrfs + Limine + Snapper

Omarchy base Btrfs subvolumes, Limine bootloader, limine-snapper-sync tying boot entries to snapshots.
btrfs-progsliminesnapperlimine-snapper-sync
Migrate reinstall requires that filesystem + bootloader from the start. If you’re not already on Btrfs+Limine, this is a rebuild.

📸 System snapshots & rollback

Omarchy Pre-update Snapper snapshots you can boot into to roll back a bad update.
Migrate depends on above only works atop the Btrfs+Snapper layout. Not bolt-on-able to a non-Btrfs root.

🔐 Secure Boot

Omarchy Documented Secure Boot enrollment path.
Migrate firmware key enrollment in UEFI + signed boot chain. Doable independently, but firmware-level and easy to lock yourself out — VM-test the concept.

™️ Branding / boot identity

Omarchy omarchy-branding-*: boot logo, about screen, screensaver identity.
Migrate skip pure Omarchy identity — no reason to adopt on your own system.
